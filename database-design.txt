================================================================================
FLASH BOOKING ENGINE (FBE) - DATABASE ARCHITECTURE & SCHEMA BLUEPRINT
================================================================================
Document Status: REFINED LOGICAL DESIGN (Google SDE-1 Standards)
Database Engine: PostgreSQL 16+
Primary Key Strategy: UUIDv7 (Used strictly for time-ordered B+Tree sequential write
locality. NEVER treated as an authorization or security mechanism).
Foreign Key Action: ON DELETE RESTRICT across all relationships (Zero cascade deletion).

================================================================================
1. IDENTITY & AUTHENTICATION
================================================================================

--------------------------------------------------------------------------------
TABLE: users
--------------------------------------------------------------------------------
Purpose: Stores user identities and hashed credentials.
Scope Rule: No admin or operator roles. All registered users are customers booking seats.

Columns:
- user_id       UUID PRIMARY KEY
- name          VARCHAR(100) NOT NULL
- email         VARCHAR(255) NOT NULL UNIQUE
- password_hash VARCHAR(255) NOT NULL
- phone         VARCHAR(20)
- status        VARCHAR(20) NOT NULL DEFAULT 'ACTIVE' 
                -- CHECK: status IN ('ACTIVE', 'BLOCKED')
- created_at    TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at    TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: user_id
- UNIQUE (email)
- INDEX idx_users_email (email)

--------------------------------------------------------------------------------
TABLE: refresh_tokens
--------------------------------------------------------------------------------
Purpose: Enables safe JWT renewal without storing plaintext sessions.
Policy: ON DELETE RESTRICT (Consistent with general foreign key policy).

Columns:
- token_id      UUID PRIMARY KEY
- user_id       UUID NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT
- token_hash    VARCHAR(255) NOT NULL UNIQUE
- expires_at    TIMESTAMPTZ NOT NULL
- revoked_at    TIMESTAMPTZ
- created_at    TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: token_id
- FK: user_id -> users(user_id) ON DELETE RESTRICT
- INDEX idx_refresh_tokens_user (user_id) WHERE revoked_at IS NULL

================================================================================
2. EVENTS & INVENTORY (RESERVED SEATING + GENERAL ADMISSION)
================================================================================

--------------------------------------------------------------------------------
TABLE: events
--------------------------------------------------------------------------------
Purpose: Scheduled concerts or matches with an authoritative booking start time.

Columns:
- event_id           UUID PRIMARY KEY
- title              VARCHAR(255) NOT NULL
- venue_name         VARCHAR(255) NOT NULL
- booking_start_time TIMESTAMPTZ NOT NULL -- Pre-sale clamp gate (e.g. 11:00:00 AM)
- event_start_time   TIMESTAMPTZ NOT NULL
- event_end_time     TIMESTAMPTZ NOT NULL
- status             VARCHAR(20) NOT NULL DEFAULT 'UPCOMING'
                     -- CHECK: status IN ('UPCOMING', 'LIVE', 'COMPLETED', 'CANCELLED')
- created_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: event_id
- INDEX idx_events_start_status (booking_start_time, status)

--------------------------------------------------------------------------------
TABLE: event_ticket_categories
--------------------------------------------------------------------------------
Purpose: Defines pricing tiers and inventory models.

Columns:
- category_id    UUID PRIMARY KEY
- event_id       UUID NOT NULL REFERENCES events(event_id) ON DELETE RESTRICT
- name           VARCHAR(50) NOT NULL -- 'VIP', 'PREMIUM', 'STANDING', 'REGULAR'
- inventory_type VARCHAR(20) NOT NULL -- 'RESERVED_SEAT' or 'GENERAL_ADMISSION'
- price_cents    BIGINT NOT NULL      -- Smallest currency unit (cents/paise)
- created_at     TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: category_id
- FK: event_id -> events(event_id) ON DELETE RESTRICT
- UNIQUE (event_id, category_id) -- Composite unique key required for composite FK validation
- UNIQUE (event_id, name)
- CHECK chk_category_price (price_cents >= 0)
- CHECK chk_inventory_type (inventory_type IN ('RESERVED_SEAT', 'GENERAL_ADMISSION'))

--------------------------------------------------------------------------------
TABLE: event_seats (Model A: Reserved Seating - A1, A2, etc.)
--------------------------------------------------------------------------------
Purpose: Physical chair inventory for a specific event. The row-locking target.

Columns:
- event_seat_id  UUID PRIMARY KEY
- event_id       UUID NOT NULL REFERENCES events(event_id) ON DELETE RESTRICT
- category_id    UUID NOT NULL
- seat_label     VARCHAR(10) NOT NULL -- e.g. "A1", "A2", "B10"
- row_label      VARCHAR(5) NOT NULL  -- e.g. "A", "B"
- seat_number    INT NOT NULL         -- e.g. 1, 2, 10
- status         VARCHAR(20) NOT NULL DEFAULT 'AVAILABLE'
                 -- CHECK: status IN ('AVAILABLE', 'HELD', 'BOOKED')
- version        INT NOT NULL DEFAULT 1 -- Optimistic concurrency control / CAS guard
- updated_at     TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: event_seat_id
- Cross-Table Consistency Guarantee:
  FOREIGN KEY (event_id, category_id) 
  REFERENCES event_ticket_categories(event_id, category_id) ON DELETE RESTRICT
  (Guarantees an event seat's category MUST belong to the EXACT same event).
- UNIQUE (event_id, seat_label) -- Guarantees no duplicate A1 in same event
- Composite Index for Fast Lookups: (event_id, status)
- Row-Level Locking Target: SELECT ... FOR UPDATE NOWAIT on (event_id, seat_label)

--------------------------------------------------------------------------------
TABLE: ga_inventory (Model B: General Admission Capacity Pool)
--------------------------------------------------------------------------------
Purpose: Counter-based inventory for standing/unreserved areas.

Columns:
- inventory_id    UUID PRIMARY KEY
- category_id     UUID NOT NULL UNIQUE REFERENCES event_ticket_categories(category_id) ON DELETE RESTRICT
- total_capacity  INT NOT NULL
- reserved_count  INT NOT NULL DEFAULT 0
- confirmed_count INT NOT NULL DEFAULT 0
- version         INT NOT NULL DEFAULT 1 -- Optimistic CAS counter
- updated_at      TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Counter Lifecycle Transitions:
1. On Hold Request (Qty N):
   UPDATE ga_inventory 
   SET reserved_count = reserved_count + N, version = version + 1
   WHERE category_id = $id AND (total_capacity - reserved_count - confirmed_count) >= N;
2. On Payment Confirmation (Qty N):
   UPDATE ga_inventory 
   SET reserved_count = reserved_count - N, confirmed_count = confirmed_count + N, version = version + 1
   WHERE category_id = $id AND reserved_count >= N;
3. On Hold Expiration / Cancellation (Qty N):
   UPDATE ga_inventory 
   SET reserved_count = reserved_count - N, version = version + 1
   WHERE category_id = $id AND reserved_count >= N;

Indexes & Constraints:
- PK: inventory_id
- UNIQUE (category_id)
- CHECK chk_ga_total_capacity (total_capacity >= 0)
- CHECK chk_ga_reserved_count (reserved_count >= 0)
- CHECK chk_ga_confirmed_count (confirmed_count >= 0)
- CHECK chk_ga_no_oversell (reserved_count + confirmed_count <= total_capacity)

================================================================================
3. BOOKING ENGINE & ALLOCATION
================================================================================

--------------------------------------------------------------------------------
TABLE: bookings
--------------------------------------------------------------------------------
Purpose: Master reservation entity managed by the Finite State Machine (FSM).

Columns:
- booking_id         UUID PRIMARY KEY
- user_id            UUID NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT
- event_id           UUID NOT NULL REFERENCES events(event_id) ON DELETE RESTRICT
- status             VARCHAR(20) NOT NULL DEFAULT 'HELD'
                     -- Valid FSM states: HELD, PAID, CONFIRMED, EXPIRED, CANCELLED, REFUND_PENDING, REFUNDED
- total_amount_cents BIGINT NOT NULL DEFAULT 0
- expires_at         TIMESTAMPTZ NOT NULL -- Set to authoritative clock_timestamp() + INTERVAL '10 minutes'
- version            INT NOT NULL DEFAULT 1 -- Optimistic concurrency guard
- created_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: booking_id
- FK: user_id -> users(user_id) ON DELETE RESTRICT
- FK: event_id -> events(event_id) ON DELETE RESTRICT
- Index for Expiration Worker:
  INDEX idx_bookings_expiry ON bookings (expires_at) WHERE status = 'HELD'
- Index for User Active Hold Quota (Scenario 18):
  INDEX idx_bookings_user_active_hold ON bookings (user_id) WHERE status = 'HELD'

--------------------------------------------------------------------------------
TABLE: booking_seats (Atomic Reserved Seat Allocation)
--------------------------------------------------------------------------------
Purpose: Junction table linking bookings to specific physical chairs.

Columns:
- booking_seat_id    UUID PRIMARY KEY
- booking_id         UUID NOT NULL REFERENCES bookings(booking_id) ON DELETE RESTRICT
- event_seat_id      UUID NOT NULL REFERENCES event_seats(event_seat_id) ON DELETE RESTRICT
- booking_status     VARCHAR(20) NOT NULL DEFAULT 'HELD'
                     -- Mirrored status from booking for database-level index filtering:
                     -- 'HELD', 'PAID', 'CONFIRMED', 'EXPIRED', 'CANCELLED', 'REFUNDED'
- price_cents        BIGINT NOT NULL -- Price snapshot at reservation time
- created_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: booking_seat_id
- FK: booking_id -> bookings(booking_id) ON DELETE RESTRICT
- FK: event_seat_id -> event_seats(event_seat_id) ON DELETE RESTRICT
- UNIQUE (booking_id, event_seat_id)
- THE PARTIAL UNIQUE ANTI-DOUBLE-BOOKING INDEX:
  CREATE UNIQUE INDEX idx_unique_active_event_seat 
  ON booking_seats (event_seat_id) 
  WHERE booking_status IN ('HELD', 'PAID', 'CONFIRMED');
  (Guarantees at the database disk level that NO seat can ever have more than ONE
  active hold or confirmation, even across concurrent transactions).

--------------------------------------------------------------------------------
TABLE: booking_items (General Admission Ticket Quantity Allocation)
--------------------------------------------------------------------------------
Purpose: Connects a booking to quantity-based General Admission tickets.

Columns:
- booking_item_id    UUID PRIMARY KEY
- booking_id         UUID NOT NULL REFERENCES bookings(booking_id) ON DELETE RESTRICT
- category_id        UUID NOT NULL REFERENCES event_ticket_categories(category_id) ON DELETE RESTRICT
- quantity           INT NOT NULL CHECK (quantity > 0)
- unit_price_cents   BIGINT NOT NULL -- Price snapshot at booking time
- subtotal_cents     BIGINT NOT NULL -- quantity * unit_price_cents

Indexes & Constraints:
- PK: booking_item_id
- FK: booking_id -> bookings(booking_id) ON DELETE RESTRICT
- FK: category_id -> event_ticket_categories(category_id) ON DELETE RESTRICT

4. FINANCIAL INTEGRITY & IDEMPOTENCY
================================================================================

--------------------------------------------------------------------------------
TABLE: idempotency_keys
--------------------------------------------------------------------------------
Purpose: Enforces exactly-once execution semantics for network retries and duplicate requests.

Columns:
- idempotency_id     UUID PRIMARY KEY
- user_id            UUID NOT NULL REFERENCES users(user_id) ON DELETE RESTRICT
- idempotency_key    VARCHAR(255) NOT NULL -- Client-generated UUID
- request_path       VARCHAR(255) NOT NULL
- request_hash       VARCHAR(64) NOT NULL  -- SHA-256 hash of payload
- status             VARCHAR(20) NOT NULL  -- 'IN_PROGRESS', 'COMPLETED', 'FAILED'
- response_code      INT                   -- Stored HTTP response code
- response_body      TEXT                  -- Cached JSON response
- booking_id         UUID REFERENCES bookings(booking_id) ON DELETE RESTRICT
- created_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- expires_at         TIMESTAMPTZ NOT NULL  -- Key TTL (e.g. 24 hours)

Indexes & Constraints:
- PK: idempotency_id
- UNIQUE (user_id, idempotency_key)
- INDEX idx_idempotency_lookup (user_id, idempotency_key)

--------------------------------------------------------------------------------
TABLE: payments
--------------------------------------------------------------------------------
Purpose: Financial transactions, gateway references, and status tracking.

Columns:
- payment_id             UUID PRIMARY KEY
- booking_id             UUID NOT NULL REFERENCES bookings(booking_id) ON DELETE RESTRICT
- gateway_transaction_id VARCHAR(255) UNIQUE
- amount_cents           BIGINT NOT NULL
- currency               VARCHAR(3) NOT NULL DEFAULT 'INR'
- status                 VARCHAR(20) NOT NULL DEFAULT 'INITIATED'
                         -- CHECK: status IN ('INITIATED', 'PENDING', 'SUCCESS', 'FAILED', 'IN_DOUBT')
- payment_method         VARCHAR(50)
- created_at             TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at             TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: payment_id
- FK: booking_id -> bookings(booking_id) ON DELETE RESTRICT
- INDEX idx_payments_booking (booking_id)
- INDEX idx_payments_in_doubt (status) WHERE status = 'IN_DOUBT'

--------------------------------------------------------------------------------
TABLE: refunds
--------------------------------------------------------------------------------
Purpose: Tracks automated refunds (e.g. payment received after expiration).

Columns:
- refund_id          UUID PRIMARY KEY
- payment_id         UUID NOT NULL REFERENCES payments(payment_id) ON DELETE RESTRICT
- gateway_refund_id  VARCHAR(255) UNIQUE
- amount_cents       BIGINT NOT NULL
- status             VARCHAR(20) NOT NULL DEFAULT 'REFUND_PENDING'
                     -- CHECK: status IN ('REFUND_PENDING', 'REFUNDED', 'FAILED')
- reason             TEXT NOT NULL
- created_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at         TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Indexes & Constraints:
- PK: refund_id
- FK: payment_id -> payments(payment_id) ON DELETE RESTRICT
- INDEX idx_refunds_payment (payment_id)

================================================================================
5. RELIABILITY, AUDITING & ASYNCHRONOUS MESSAGING
================================================================================

--------------------------------------------------------------------------------
TABLE: audit_logs (Tamper-Evident Ledger)
--------------------------------------------------------------------------------
Purpose: Append-only cryptographic ledger of every state transition.

Columns:
- audit_id      UUID PRIMARY KEY
- entity_type   VARCHAR(50) NOT NULL -- 'BOOKING', 'PAYMENT', 'SEAT'
- entity_id     UUID NOT NULL
- actor_id      UUID NOT NULL        -- User ID or System Identity
- action        VARCHAR(50) NOT NULL -- 'HOLD_SEAT', 'CONFIRM_PAYMENT', 'EXPIRE_HOLD'
- old_state     VARCHAR(50)
- new_state     VARCHAR(50)
- reason        TEXT
- metadata      JSONB
- previous_hash VARCHAR(64) NOT NULL
- current_hash  VARCHAR(64) NOT NULL -- SHA256(prev_hash + entity_id + new_state + actor_id + timestamp)
- created_at    TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP

Permissions & Security:
- Application database role granted INSERT and SELECT ONLY.
- UPDATE and DELETE permissions revoked on audit_logs.

--------------------------------------------------------------------------------
TABLE: outbox_events (Transactional Outbox Pattern)
--------------------------------------------------------------------------------
Purpose: Eliminates dual-write anomalies by writing domain events in same DB transaction.

Columns:
- outbox_id      UUID PRIMARY KEY
- aggregate_type VARCHAR(50) NOT NULL -- 'BOOKING', 'PAYMENT'
- aggregate_id   UUID NOT NULL        -- Partition key for Kafka (booking_id)
- event_type     VARCHAR(50) NOT NULL -- 'BookingHeld', 'PaymentConfirmed', 'BookingExpired'
- payload        JSONB NOT NULL
- status         VARCHAR(20) NOT NULL DEFAULT 'PENDING' -- 'PENDING', 'PUBLISHED', 'FAILED'
- retry_count    INT NOT NULL DEFAULT 0
- created_at     TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
- published_at   TIMESTAMPTZ

Indexes & Constraints:
- PK: outbox_id
- INDEX idx_outbox_pending ON outbox_events (created_at) WHERE status = 'PENDING'
